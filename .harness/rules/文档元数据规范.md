# 文档元数据规范

> 本规范是 doc-gardening-agent 新鲜度检查、漂移检测、索引完整性检查的**数据基础**。
> 无元数据的文档视为"不可检查"，纳入 doc-gardening 告警清单。

## 1. 必备字段

每本 Markdown 文档**第一行必须**是 frontmatter 起始符 `---`，包含以下字段：

```yaml
---
title: 文档标题
status: active | draft | deprecated | archived
last_updated: YYYY-MM-DD
owner: 责任人或角色
summary: 一句话功能简介（≤50字，说明本文档解决什么问题）
---
```

| 字段 | 规则 |
|------|------|
| title | 与正文一级标题一致 |
| status | `active` 活文档；`draft` 草稿；`deprecated` 废弃保留（仅留指针、不再维护的文档）；`archived` 历史快照（changes/shipped 默认） |
| last_updated | **任何实质修改必须同步更新此日期**，这是新鲜度检查的唯一依据 |
| owner | 责任角色（如 ddd-team / harness / doc-gardening） |
| summary | 给索引和检索用的一句话，禁止复制标题 |

## 2. 豁免与共存

| 类型 | 规则 |
|------|------|
| 生成物（AST_INDEX.md、COMPLIANCE_REPORT.md 等脚本产物） | 豁免，以生成脚本为准，禁止手改 |
| 需求分析报告（.harness/requests/**/summary.md） | 沿用 doc-analysis 规定的 frontmatter（complexity/status/intent_aligned 等），不套本规范 |
| Agent 定义文件（agents/*.md） | `role`/`activates`/`trigger_keywords` 字段与本规范字段**共存于同一 frontmatter 块** |
| 变更文档（changes/active/**） | 沿用 changes 模板 frontmatter（feature/status/created/owner）， shipped 后 status 改 archived |

## 3. doc-gardening 检查项（数据基础来自本规范）

| 检查 | 依据字段 | 告警阈值 | 执行工具 |
|------|---------|---------|---------|
| 过期扫描 | last_updated | 活文档超 90 天未更新 | `python .harness/tools/doc_freshness_scan.py` |
| 状态一致性 | status | deprecated 文档仍被指针引用 | `python .harness/tools/doc_freshness_scan.py` |
| 索引完整性 | summary | 缺失或 ≥50 字 | `python .harness/tools/doc_link_check.py` |
| 元数据缺失 | 全字段 | 无 frontmatter = 直接告警 | `python .harness/tools/doc_freshness_scan.py` |
