# 工程结构规范

## 项目模块总览（接入后按实际改写）

```
{your-project}/
├── {module-a}/          # 【业务模块】COLA DDD 四层（示例：order/ 订单模块）
├── {module-b}/          # 【业务模块】COLA DDD 四层（示例：user/ 用户模块）
├── .harness/            # 【AI Agent 工作区】agents/rules/specs/wiki/changes/skills
├── CLAUDE.md            # 【入口】意图路由 SSOT（Claude Code 自动加载）
├── AGENTS.md            # 【入口】项目代码地图与治理索引
└── pom.xml              # 父 POM
```

## COLA DDD 四层模块结构

```
{module}/
├── pom.xml
├── API_REGISTRY.md               # API 端点注册表
└── src/main/java/com/example/{module}/
    ├── {Module}Application.java  # 启动类
    ├── interfaces/               # 【接口层】HTTP 协议适配
    │   ├── rest/                 #   *Controller.java (@RestController)
    │   ├── dto/                  #   *Request.java, *Response.java
    │   └── assembler/            #   *Assembler.java (DTO ↔ Command/Domain)
    ├── application/              # 【应用层】技术编排
    │   ├── DomainConfig.java     #   领域 Bean 装配 (唯一框架接触点)
    │   └── service/              #   *AppService.java, *Command.java (record)
    ├── domain/                   # 【领域层】纯业务逻辑 (零框架依赖)
    │   ├── model/                #   聚合根/实体/值对象/DomainException
    │   ├── service/              #   *DomainService.java (跨实体编排)
    │   ├── repository/           #   *Repository.java (仓储接口)
    │   ├── acl/                  #   *Acl.java (防腐层接口)
    │   ├── gateway/              #   *Gateway.java (外部网关接口)
    │   ├── event/                #   领域事件定义
    │   └── policy/               #   领域规约
    │       └── validation/       #   *Spec.java (纯函数校验)
    └── infrastructure/           # 【基础设施层】技术实现
        ├── persistence/           #   Repository 实现
        │   ├── *RepositoryImpl.java
        │   ├── po/               #   *PO.java (MyBatis-Plus @TableName)
        │   └── mapper/           #   *Mapper.java (BaseMapper<PO>)
        ├── aclImpl/              #   *AclImpl.java (ACL 实现)
        ├── gateway/              #   *GatewayImpl.java (Gateway 实现)
        ├── eventImpl/            #   领域事件发布实现
        └── idempotency/          #   幂等性/分布式锁实现
```

## 模块边界（示例，按项目改写）

| 模块 | 依赖 | 被依赖 | 允许包含 | 严禁包含 |
|------|------|--------|---------|---------|
| **order** (示例) | common | root | 全部四层代码 | 其他业务模块的类 |
| **user** (示例) | common | root | 全部四层代码 | order 的类 |
| **common** (待拆分) | 无 | 所有模块 | 工具类、注解、枚举、异常、基础实体 | Controller、业务逻辑、ACL 实现 |

## 命名约定

| 层级 | 命名模式 | 示例 |
|------|----------|------|
| Controller | `{Feature}Controller` | `OrderController`, `LoginController` |
| AppService | `{Feature}AppService` | `OrderAppService`, `LoginAppService` |
| Command | `{Feature}Command` (record) | `OrderSubmitCommand`, `LoginWithSmsCommand` |
| Assembler | `{Feature}Assembler` | `OrderAssembler`, `LoginAssembler` |
| 聚合根 | `{Entity}` | `Order`, `UserAccount` |
| 值对象 | `{Value}` (record) | `OrderResult`, `ChannelInfo`, `UserInfo` |
| Repository 接口 | `{Entity}Repository` | `OrderRepository` |
| Repository 实现 | `{Entity}RepositoryImpl` | `OrderRepositoryImpl` |
| ACL 接口 | `{Feature}Acl` | `SmsAcl`, `FileStorageAcl` |
| ACL 实现 | `{Feature}AclImpl` | `SmsAclImpl`, `FileStorageAclImpl` |
| Gateway 接口 | `{Feature}Gateway` | `PaymentGateway` |
| Gateway 实现 | `{Feature}GatewayImpl` | `PaymentGatewayImpl` |
| Policy/Spec | `{Feature}Spec` | `LoginValidationSpec`, `OrderSubmitSpec` |
| PO | `{Entity}PO` | `OrderPO`, `UserAccountPO` |
| Mapper | `{Entity}Mapper` | `OrderMapper` |
| DTO Request | `{Feature}Request` | `OrderSubmitRequest`, `LoginSmsRequest` |
| DTO Response | `{Feature}Response` | `OrderSubmitResponse`, `LoginSmsResponse` |

## 新增模块指南

如需新增业务模块 `{module}`：
1. 父 POM 添加 `<module>{module}</module>` 和依赖声明
2. 包名遵循 `com.example.{module}`（按项目实际 groupId 调整）
3. 严格遵循 COLA DDD 四层目录结构
4. 在 `domain/acl/` 中定义所有外部服务接口
5. 在 `application/DomainConfig.java` 中注册所有领域 Bean
6. 创建 `API_REGISTRY.md` 登记 API 映射关系
7. 禁止 `{module}` 反向依赖其他业务模块
