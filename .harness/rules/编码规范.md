# 编码规范

## 后端 Java 编码规范

### 命名约定

| 元素 | 规范 | 示例 |
|------|------|------|
| 包名 | 全小写 | `com.example.order.domain.model` |
| 类名 | PascalCase | `OrderAppService`, `DomainException` |
| 接口名 | PascalCase + 语义后缀 | `OrderRepository`, `SmsAcl`, `PaymentGateway` |
| 方法名 | camelCase | `submitOrder()`, `checkIdentity()` |
| 常量 | UPPER_SNAKE_CASE | `CODE_TAG`, `MSG_TAG` |
| 变量 | camelCase | `mobile`, `channelId` |
| 枚举 | PascalCase | `ErrorCode`, `OrderStatus` |
| Record | PascalCase | `OrderSubmitCommand`, `SendSmsResult` |

### Controller 规范 (interfaces/rest/)

- 🔴 极薄：方法体 ≤ 5 行
- 🔴 仅做三件事：接收请求 + Assembler 转换 + 调 AppService
- 🔴 使用 `@RestController` + `@Tag` + `@Operation` (SpringDoc)
- 🔴 异常由 GlobalExceptionHandler 统一处理

```java
@RestController
@Tag(name = "订单")
@RequestMapping("/api/orders")
public class OrderController {
    private final OrderAppService orderAppService;
    private final OrderAssembler orderAssembler;

    @Operation(summary = "提交订单")
    @PostMapping("/submit")
    public OrderSubmitResponse submit(@RequestBody OrderSubmitRequest request) {
        OrderSubmitCommand command = orderAssembler.toCommand(request);
        OrderResult result = orderAppService.submit(command);
        return orderAssembler.toResponse(result);
    }
}
```

### AppService 规范 (application/service/)

- 🔴 编排而非实现：每行一个关注点
- 🔴 零循环零判断（业务规则在 domain 层）
- 🔴 `@Service` + 构造器注入
- 🔴 编排顺序：Policy校验 → 领域对象创建/状态流转 → Repository持久化 → ACL副作用

```java
@Service
public class OrderAppService {
    private final OrderSubmitSpec orderSubmitSpec;
    private final OrderRepository orderRepository;
    private final SmsAcl smsAcl;
    private final UserCenterAcl userCenterAcl;

    public OrderResult submit(OrderSubmitCommand command) {
        UserInfo user = userCenterAcl.getUser(command.userId());
        Order order = Order.register(command.userId(), command.items());  // 领域对象创建
        orderSubmitSpec.validate(order, user);                            // Policy 校验
        orderRepository.save(order);                                      // 持久化
        smsAcl.sendSmsCode(user.mobile(), "order_submitted");             // ACL 副作用
        return order.toResult();
    }
}
```

### Domain Model 规范 (domain/model/)

- 🔴 纯 POJO，零框架依赖
- 🔴 聚合根：工厂方法 `register()`（创建）/ `rebuild()`（从持久化重建）
- 🔴 行为方法：状态流转 + 不变量保护（违反抛 DomainException）
- 🔴 值对象：优先使用 JDK 21 record（不可变）
- 🔴 getter 无 setter，状态变更通过行为方法

### Policy/Spec 规范 (domain/policy/validation/)

- 🔴 纯函数：不调 ACL、不调 Repository、不碰 IO
- 🔴 接收预取数据作为参数
- 🔴 校验失败抛 DomainException

### ACL 规范 (domain/acl/)

- 🔴 接口定义在 domain/acl/，实现在 infrastructure/aclImpl/
- 🔴 返回领域值对象（domain/model 下的类型）
- 🔴 绝不返回外部 DTO

### Repository 规范 (domain/repository/)

- 🔴 接口定义在 domain/repository/，实现在 infrastructure/persistence/
- 🔴 返回领域对象（非 PO），方法命名用领域语言
- 🔴 实现类负责 PO ↔ Domain 双向转换

### 异常处理规范

```
DomainException (领域异常, code + message)
  └── 由 GlobalExceptionHandler 统一处理
```

- 🔴 业务逻辑中使用 `DomainException` + 错误码 + 错误描述
- 🔴 禁止 `catch(Exception)` 兜底
- 🔴 禁止 `printStackTrace`
- 🔴 禁止一个异常打多次日志

## Git 提交规范

```
<type>(<scope>): <subject>

类型:
  feat     新功能
  fix      修复 Bug
  docs     文档修改
  style    代码格式（不影响功能）
  refactor 重构
  perf     性能优化
  test     测试相关
  chore    构建/工具/依赖

示例:
  feat(order): 新增订单取消功能
  fix(user): 修复登录验证码校验异常
```

## 代码审查清单

- [ ] Controller 极薄（≤5行）
- [ ] AppService 编排而非实现（零循环零判断）
- [ ] domain 层无 Spring 注解
- [ ] Policy 纯函数（无副作用）
- [ ] ACL 返回领域值对象
- [ ] DomainConfig 注册了新增的领域 Bean
- [ ] 异常使用 DomainException
- [ ] 命名符合项目约定
- [ ] 敏感字段（手机号/身份证）脱敏
- [ ] 添加了必要的 JavaDoc 注释
